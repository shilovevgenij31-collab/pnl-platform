# Report Quality Checklist

Инструкция для ручной оценки качества P&L и Goldratt-отчётов.
Используй при тестировании после генерации нового отчёта.

---

## P&L Checklist

### Согласованность данных

- [ ] Dashboard KPI и AI-текст не противоречат друг другу
- [ ] Количество периодов в тексте совпадает с количеством колонок в таблице
- [ ] Средняя выручка/прибыль/маржа в тексте соответствует данным из источника
- [ ] Нет fake zeros: если данных нет — написано "не рассчитано", а не 0

### Диагноз соответствует ситуации

- [ ] **Прибыльный бизнес**: AI не называет его убыточным
- [ ] **Бизнес выше breakeven**: AI не говорит "первый шаг — выйти в ноль"
- [ ] **Все месяцы прибыльные**: AI не пишет "прибыль появляется точечно"
- [ ] **Маржа ниже цели**: фокус на качестве маржи, а не на выживании
- [ ] **Смешанные периоды**: AI не обобщает "системно убыточен", если большинство месяцев прибыльны

### Качество рекомендаций

- [ ] Нет универсальных советов типа "нужно провести анализ", "следует оптимизировать расходы"
- [ ] Нет "роста ради роста": рост выручки рекомендован только с проверкой маржи
- [ ] Первые действия конкретны: "получить расшифровку статьи X", "проверить маржу по направлению Y"
- [ ] Рекомендации адаптированы под тип бизнеса (marketplace ≠ сервис ≠ офлайн)

### Проверка плана предпринимателя

- [ ] Если `founderPlan` заполнен — AI его проанализировал
- [ ] Дан явный ответ: план верный / правильное направление / лечит не то место
- [ ] Нет молчаливого игнорирования плана предпринимателя

### Нет утечки демо-контента

- [ ] Нет "клубов", "Лига Миров", "УК по клубам" если бизнес не клубная сеть
- [ ] Нет "WB/Ozon комиссий" если бизнес не маркетплейс
- [ ] Company name в отчёте совпадает с тем, что ввёл пользователь

## Goldratt Checklist

### Структура вывода

- [ ] Названо одно ограничение — не список из 5 проблем
- [ ] Дан прямой вердикт: "Вы правы" / "Вы близко, но называете симптом" / "Вы лечите не то место"
- [ ] Вердикт не "собственник как ограничение" по умолчанию без прямых симптомов

### Проверка гипотезы

- [ ] Если `bottleneckGuess` заполнен — AI его использовал
- [ ] Если `founderPlan` заполнен — AI его использовал
- [ ] Вердикт объясняет почему (2–3 предложения логики)

### Качество первых действий

- [ ] Нет "провести анализ", "разработать структуру", "определить метрики"
- [ ] Действия соответствуют вердикту:
  - "Вы правы" → фокусируют правильное решение
  - "Вы близко" → сначала остановить лечение симптома
  - "Вы лечите не то место" → заморозить вредное действие
- [ ] 48ч: можно сделать сегодня без согласований
- [ ] 7 дней: проверка гипотезы или назначение ответственного
- [ ] 14 дней: закрепление или делегирование

### Нет опасных советов

- [ ] Нет "нанимать людей" как первый шаг, если ограничение не снято
- [ ] Нет "увеличить маркетинг" как первый шаг, если ограничение не в спросе
- [ ] Нет "нужно больше данных" как главного вывода

## Тестовые сценарии для ручной прогонки

### P&L-сценарии

| # | Описание | Что проверять |
|---|----------|---------------|
| 1 | Прибыльный marketplace, маржа ниже цели | Нет "убыточен"; фокус на марже по каналам |
| 2 | Убыточный сервисный бизнес | Чёткий диагноз: расходы или выручка |
| 3 | Mixed: 2 прибыльных, 2 убыточных месяца | Не "системно убыточен"; сравнение условий |
| 4 | Рост выручки, падение маржи | Указаны статьи, растущие быстрее выручки |
| 5 | Падение выручки, нормальная маржа | Акцент на спросе/канале, не на расходах |

### Goldratt-сценарии

| # | Описание | Что проверять |
|---|----------|---------------|
| 1 | Собственник как ограничение (явные симптомы) | Прямой вердикт; конкретные 48ч действия |
| 2 | Лиды есть, конверсия слабая | Ограничение — продажи/оффер, не собственник |
| 3 | Производство не успевает | Ограничение — delivery/производство |
| 4 | Много маркетинга, слабый оффер | Ограничение — продукт/оффер, не маркетинг |
| 5 | Команда не закрывает delivery | Ограничение — исполнение, а не продажи |

## Как прогнать тест

1. Открыть `/analyze?agent=pnl` или `/analyze?agent=goldratt`
2. Заполнить форму тестовым сценарием (или использовать кнопку Fill Test Data)
3. Сгенерировать отчёт
4. Пройти по чеклисту выше
5. Зафиксировать несоответствия в задаче / issue

> Этот чеклист покрывает качество интерпретации, а не UI. Для UI-тестирования используй отдельный smoke-test по route'ам.
